# Tgrad Experiment Result

## Verdict

historical result: yes

current promoted result: inconclusive

The original release memo concluded “yes,” but its committed evidence does
not certify this repository. A partial regeneration produced 11/37 files from
their current scripts, but 26 still name an absent commit, 76/115 recorded
hashes cannot be resolved, and 28 roll-ups disagree. That verdict is retained
above as historical data, not as a current claim.

The current tree has stronger codegen architecture and direct semantic
evidence: all 11 sentinels are generated by Lean, generated source differs
from the captured tinygrad source, and 240 MB of output compared bit-for-bit.
A new promoted release result requires a paired, repeatable performance
experiment followed by complete serial evidence regeneration.

## Scope

Implemented by the current product tree:

- bf16 input/output with fp32 accumulation.
- Apple Silicon Metal backend.
- Contiguous matmul plus view-composed matmul through transpose,
  reshape, permute, expand, and slice.
- Parametric generated sentinel and TC-general manual-load kernels, scalar
  fallback paths, and captured kernels retained only as executable oracles.
- BEAM=0-style dispatch heuristic.

## Where Lean Helped

1. **Generated ShapeSentinel routing is exhaustive.**
   - File: `Tgrad/Pipeline.lean`
   - Negative case: rejecting a sentinel breaks
     `generatedKernelDeclFor_accepts_all_sentinels` at build time.

2. **Generated launch facts are checkable by `decide`.**
   - File: `Tgrad/Renderer/MatmulTc.lean`
   - Negative case: changing generated grid or threadgroup geometry breaks
     `tcLaunchDims_matches_all_captured` or the nonzero launch theorem.

3. **Metal rendering is a pure function over typed declarations.**
   - File: `Tgrad/Renderer/Metal.lean`
   - Negative case: moving renderer behavior to filesystem IO would
     change the `renderKernel : KernelDecl -> String` contract and trip
     L12 anti-replay checks.

4. **Movement operations have typed constructors.**
   - File: `Tgrad/UOp.lean`
   - Negative case: replacing structured slice/reshape/permute data with
     untyped payloads removes the consumer exhaustiveness the view gates
     rely on.

5. **Scalar view matmul is parameterized by index UOps.**
   - File: `Tgrad/Renderer/MatmulScalar.lean`
   - Negative case: using one generic kernel cache key for all view
     variants collides different view formulas; L14.B.3 catches this via
     distinct view tags and correctness checks.

6. **TC stores carry typed indices and a non-aliasing obligation.**
   - File: `Tgrad/Renderer/MatmulTc.lean`
   - Negative case: colliding store offsets fail `tileStoreOffsets_nodup`;
     wrong-but-distinct placement fails the executable differential.

## Where Lean Did Not Yet Help

- The BEAM=0 heuristic is ported and gate-tested, not extensionally
  compared against every possible tinygrad schedule.
- View rangeify covers the operations exercised by the committed gates,
  not every movement pattern in tinygrad.
- The Python wrapper still owns host-side marshalling and convenience
  accessors; Lean owns the typed runtime path and dispatch decisions.

## Performance Interpretation

No current performance-parity result is promoted. The historical gates time
different work on the two sides: Tgrad dispatches a precompiled generated
kernel, while un-JIT-ed tinygrad rebuilds and schedules a graph inside its
timed region. They also compare live runs with frozen baselines and mix
statistics across gates.

The serial regeneration made the repeatability failure empirical. Three
consecutive L11 runs at the same `e90607f` revision, `30/30` configuration,
GPU, and frozen baseline produced 2/50, 25/50, and 10/50 misses, with
`ratio_max` 1.655, 3.667, and 2.552. L12's generated-path diagnostic changed
from median/max 2.38/4.24 and 37 misses at `1/1` to 1.18/1.41 and zero misses
at `30/30`, without a code change. A single threshold verdict is therefore
not reproducible. The honest current description is roughly 1.2–1.5x the
frozen baseline, noisy and sometimes worse; the old 0.9354 median was the
captured-kernel replay path, not codegen.

The next result must measure both systems live and interleaved at symmetric
boundaries, retain paired raw samples, estimate within-run and between-run
variance over repeated sessions, and predeclare any threshold from that
variance. If variance is too large, the result is indeterminate—not a tuned
green.

## Not Claimed

- **Full tinygrad replacement**: this is the bf16 Metal matmul slice.
- **Arbitrary dtypes**: bf16 input/output with fp32 accumulation only.
- **Non-Metal backends**: no CUDA, ROCm, OpenCL, or CPU runtime.
- **Autograd**: forward matmul only.
- **Full BEAM**: no `BEAM=N` search.
- **Proof of broad equivalence**: key invariants are typed and
  gate-tested, but the project does not assert broad semantic equality
  with tinygrad.

## Next Move

Build the paired generated-kernel measurement harness and characterize its
repeatability serially. Only then regenerate all 37 gate artifacts on one
exact clean tree and make provenance validation fatal. Compatibility growth
continues through the checked work graph rather than by reviving the
historical “result: yes” snapshot.
